# مراجعة أريب وتحويله إلى محصول فاخر

## مصادر المراجعة

- `areeb-system-v2` مرتبط بـ `a7madshiref001-ctrl/areeb`؛ آخر نسخة مراجعة: `8a01ea3`.
- تمت مراجعة النسخة الأقدم `areeb-system` للمقارنة؛ ليست مستودع Git مستقلًا.
- المصدر المستهدف `a7madshiref001-ctrl/luxury-crop-menu` عند `e5fa9f0`؛ دليل README القديم ذكر ٥٠ صنفًا بينما البيانات الفعلية تضم ٦٤ صنفًا في ١٠ أقسام.
- ملفات أريب الأساسية: `data/menu.js`، `data/sales.js`، `assets/sys.js`، `assets/menu.js`، `assets/owner.js` والصفحات والتنسيقات المرتبطة.
- موارد محصول فاخر: `data/menu.json` والأصول الأربعة للوجو، وروابط Instagram وMaps الموجودة بالمصدر.

## ما يفعله أريب الأصلي

`MENU` يحمل البراند والأقسام. `SALES` يحمل إعدادات الطلب والعروض والإضافات والاقتراحات والكومبو والولاء والكوبون والتقييم وحاسبة العائد. `sys.js` يبني فهرسًا، يخزن أحداثًا وطلبات محليًا، يولد بيانات عرض ويجمعها؛ `menu.js` يرسم المنيو والسلة وينشئ رسالة واتساب؛ `owner.js` يرسم اللوحة ويتحكم في أسعار وتوفر المنيو.

## النتائج والمعالجة

| الملاحظة في المصدر | أثرها | المعالجة في النسخة الجديدة |
|---|---|---|
| البيانات في localStorage وBroadcastChannel | التزامن بين تبويبات نفس المتصفح فقط؛ جوال العميل لا يرسل إلى جهاز الإدارة | API وSQLite مركزية، مع تحديث دوري بين الأجهزة |
| `BYNAME` والأسعار والتوفر مربوطون بالاسم | يتداخل الساخن والبارد والأصول المتكررة | IDs الأصلية المستقرة في السلة والتسعير والإحصاءات |
| فتح واتساب يسجل الطلب والمبيعة ونجمة الولاء | لا دليل على إرسال الرسالة أو دفع الفاتورة | رقم طلب محفوظ بالسيرفر، مراحل تشغيل، المبيعات والولاء بعد التسليم والدفع |
| رقم واتساب وقوقل placeholder | طلبات وتقييمات قد تذهب إلى رابط خاطئ | رقم المقهى فارغ حتى ضبطه، استخدام Maps المصدر، لا إرسال عشوائي |
| بيانات عرض مولدة مفعلة في اللوحة | أرقام تبدو حقيقية؛ إعادة التوليد تمسح السجلات | لا توليد بيانات تشغيل افتراضية؛ اختبارات في قاعدة مستقلة |
| أسعار محفوظة بالسلة بلا إعادة تحقق | يمكن الإرسال بسعر قديم أو صنف نفد | إعادة تسعير وتحقق بالسيرفر مع رفض فرق الإجمالي وتحديث السلة |
| كميات وأسعار وتعديلات غير موثقة | تضارب بيانات أو تلاعب | تحقق صارم، حساب بالهللات، حد للكمية، تعارض إصدار 409 |
| عرض متكرر يوميًا وساعة الجهاز المحلية | انتهاء العرض لا يمثل فترة تشغيل حقيقية | بداية ونهاية مطلقتان، عرض بتوقيت السعودية، حساب السيرفر |
| كوبون يظهر كرسالة بلا تطبيق مالي | وعد خصم لا تنفذه السلة | كود فعلي، حد أدنى وانتهاء، خصم موزع بالهللات؛ لا يجمع مع العرض |
| الولاء يتقدم قبل تأكيد الطلب | مكافآت غير مستحقة أو متكررة | أختام من المكتمل، وسجل صرف يحسب الأختام المستخدمة |
| توجيه التقييم حسب عدد النجوم | مراجعات منخفضة لا تحصل على خيار Google | نفس خيارات Google والإدارة للجميع |
| شاشة افتتاح وتأثيرات تؤخر التصفح | احتكاك في زيارة QR السريعة | فتح مباشر للمنيو؛ حركة محدودة واحترام تقليل الحركة |
| HTML inline handlers وتصدير CSV غير معالج | صعوبة CSP واحتمال إدخال نص غير آمن | أحداث منفصلة، تهريب النصوص، CSP ومكافحة CSV formula injection |
| لوحة المنيو القديم تحوي مفتاح نشر GitHub في JS | حماية الدخول الأمامية لا تخفي السر | إزالة المفتاح والمسار القديم؛ الجلسات تتحقق بالسيرفر |
| تقديرات غذائية خاطئة أو غير معتمدة | عرض أرقام بمظهر موثوق | إخفاء غير المعتمد، تصحيح حليب/كافيين وإتاحة الاعتماد للإدارة |

## قرارات النقل

- لم ننسخ محرك أريب حرفيًا؛ أُعيد تنفيذ سلوكه المفيد مع إصلاح حدود التخزين والتسعير والمصادقة.
- لم ننقل عروض أريب أو أسعار إضافاته أو كومبوهاته إلى محصول فاخر؛ لا دليل أنها معتمدة لدى الكافيه. الاقتراحات تضيف أصناف محصول فاخر بأسعارها الفعلية. العروض والكوبونات والولاء جاهزة لكن معطلة افتراضيًا.
- الـ٦٤ صنفًا و١٠ أقسام والأسعار محفوظة من المصدر؛ إزالة مسافات زائدة، وتحسين ترجمات منها إسبريسو كولومبي كان مترجمًا El Salvador.
- أسماء الوصفات وأصول البن حفظت؛ الصور توضيحية مولدة وليست إثباتًا لشكل التقديم أو المكونات.
- HTML/CSS/JS خفيف للعميل، Node 24 + SQLite للسيرفر؛ دون خدمة خارجية إلزامية أو مفاتيح API.
- QR يولد بالسيرفر نفسه ولا يرسل رابط المقهى إلى طرف ثالث.

## ما تم اختباره وحدود المراجعة

- اختبارات أرقام الطلبات ومنع تكرار الإرسال، خصوصية بيانات المتابعة، مصادقة الإدارة، CSRF، حجب ملفات السيرفر والبيانات والأسرار.
- تمييز الساخن والبارد، نفاد الصنف، كميات غير صالحة، السعر المعدل، انتهاء العروض، الكوبونات وتقريب الهللات.
- الإيراد من المكتمل فقط، صرف الولاء مرة واحدة، لقطة SQLite وقراءة النسخة، بقاء البيانات بعد إعادة تشغيل السيرفر.
- استخدام حقيقي آلي على Chrome المكتبي والمحمول: البحث واللغة والمفضلة والسلة والطلب ولوحة الإدارة وتغيير التوفر من متصفح مستقل.
- تحرير أصناف وأقسام وحقن نص HTML غير ضار، تفعيل كوبون وطلب به، إنشاء QR وتنزيله.
- فحص بصري لصور المنتجات والمنيو واللوحة. أُعيد توليد صورة الفريدو بلا حليب والهوت شوكليت بالإسبريسو كمنتج ساخن.
- لا يمثل ذلك اختبار اختراق مستقلًا أو اختبار ضغط عاليًا. بناء Docker لم يُنفذ. نُشرت نسخة تصفح على GitHub Pages؛ السيرفر يعمل محليًا.

## تشغيل فعلي

الخطوة التشغيلية المتبقية هي وضع السيرفر على استضافة HTTPS ذات قرص دائم، وضبط كلمة مرور الإدارة وعدد الطاولات ورقم المقهى وشروط العروض. المنيو القديم العام لم يُستبدل في هذه الجلسة. يجب إلغاء مفتاح GitHub القديم لدى مالكه لأنه قد يبقى في تاريخ Git.


## مراجعة الاستخدام الموسعة — ١٦ سبتمبر ٢٠٢٦

- فحص فتح تفاصيل وصور كل الأصناف الـ٦٤ على الكمبيوتر والموبايل، اللغة والترتيب والمظهر الداكن والبيانات المحلية التالفة.
- إصلاح فقدان الرد بعد قبول الطلب: إعادة محاولة بنفس المفتاح مع حماية الطلب غير المؤكد من التعديل حتى معرفة نتيجته.
- استعادة الاتصال بدون إعادة تحميل، منع تجاوز ٢٠ وحدة عبر سطور مختلفة لنفس الصنف، وإزالة تفاصيل صنف حُذف من جهاز آخر.
- إصلاح حقل الطاولة المخفي الذي كان يعرقل طلب الاستلام، وترجمة خيارات المشروبات.
- منع رد متابعة متأخر من فتح نافذة أُغلقت، وحماية شاشة تفاصيل الطلب أثناء تغيير حالته.
- حماية تغييرات الإدارة غير المحفوظة، توضيح تعارض تعديلات جهازين، إصلاح إغلاق القائمة الجانبية بالموبايل، وفشل تسجيل الخروج القابل للمحاولة مجددًا.
- تصحيح توزيع هللات الخصم حتى لا يصبح إيراد صنف مجاني سالبًا، وقراءة JSON العربي المرسل على أجزاء بدون إفساد حروفه.
- تصحيح QR فارغ الطاولة بحيث لا يحتفظ بطاولة قديمة داخل الرابط، ورفض الصفر، وإيضاح حدود صفحة الإدارة على GitHub Pages.
